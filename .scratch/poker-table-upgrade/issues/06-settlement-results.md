# 06: 独立结算结果区

Status: done
Type: task
Blocked by: [04：桌面与手机六座位布局及操作区](04-responsive-six-seat-table.md)
Spec: [升级规格](../spec.md) — U8、U9、U10；UAC26、UAC27（结果部分）

**What to build:** 玩家在操作栏下方直接查看结算结果、赢家及获得筹码，按既定权限核对牌型、Best Five、本局投入和结算余额，继续查看牌桌直到房主开始下一局。

## Acceptance criteria

- [x] UAC26：结果区位于“你的操作”下方，突出每名赢家及获得筹码；各项结果来自服务器确认的已结算视图，不由页面重新比牌、分池或记账。
- [x] UAC26：摊牌按既定公开范围展示未弃牌参赛者手牌、牌型和Best Five，同时呈现本局投入、所得筹码及结算余额；弃牌者不向其他人公开暗牌。
- [x] UAC26：提前胜出不强制亮任何人的手牌，本人仍可看自身允许查看的手牌；无权看到的牌型／Best Five不由前端伪造或推算。
- [x] UAC26：结果保留至下一局开始；期间刷新、重连、接管或离房不改写已保存奖项和结算余额，重连将当前可用余额设100与历史结算余额可区分。
- [x] 新局只有合条件房主可以手动开始；新局开始后替换旧结果，既有开局限制、服务器权限和请求幂等性保持。
- [x] UAC27（本票部分）：桌面1280及手机390宽均可阅读多人／并列赢家结果，纵向滚动后可完成下一局操作，无页面横向溢出。

## Public test boundaries

- 复用固定牌序，通过公开命令与身份视图制造摊牌、平局、弃牌及提前胜出，检查原始HTTP／WebSocket载荷的公开范围。
- 浏览器观察结果位置、赢家、金额、Best Five与结果保留／替换；预期奖项来自独立手算，不能复制结算算法。
- 不要求票02或05先完成：本票呈现已有确认的奖项和牌信息，不自行改变分配策略；已完成的随机零头与卡片呈现须保留，其组合在票07复核。
