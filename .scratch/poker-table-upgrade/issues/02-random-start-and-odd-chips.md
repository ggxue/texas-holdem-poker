# 02: 每局随机起点与统一零头顺序

Status: done
Type: task
Blocked by: [01：五真人入房、开局与房主交接](01-five-human-room.md)
Spec: [升级规格](../spec.md) — U1、U3、U4、U10；UAC06–12、UAC03–04（起点部分）

**What to build:** 每局从本局参赛者中等概率选择一次行动起点，包括机器人；所有下注轮沿同一固定座位循环推进，并列赢家的零头也沿该循环分配。玩家通过当前行动、合法动作和结算奖项看到一致的顺序。

## Acceptance criteria

- [x] 成功开局只确定一次起点，候选为全部本局参赛者，包含付底注后全押者及机器人，排除空位和待局者。生产策略等概率，不能把“各候选可强制选到”当作等概率策略的证明。
- [x] UAC06：六人局受控抽中真人4，各轮按4、5、机器人、1、2、3循环；进入新轮不重抽，页面的行动者及合法动作来自服务器确认状态。
- [x] UAC07：受控抽中机器人时它可成为起点；部分真人参赛时循环正确跳过空席。
- [x] UAC08：底注后全押的起点仍保持，后续轮起点弃牌或离房时沿循环找到可行动者，不重抽；欠注者先回应，既有Runout和提前胜出保持。
- [x] UAC09：真人4先Check、真人5Bet10后，真人4仍按循环获得Call／Fold；已跟齐者不重复获得过牌机会。
- [x] UAC10、UAC03–04（起点部分）：刷新、重连、接管、中途入房和退出不改变本局起点及顺序；已有真人期限不延长，成功重新入房的余额仍按内存决定设100。
- [x] UAC11：起点真人4，底池21，真人4与真人1并列最强、其余弃牌时，分别得11和10，其余0；不退投入，不增发，不向非赢家分零头。
- [x] UAC12：起点为非赢家或已离房者时，零头沿同一循环跳过非赢家，只给并列最强赢家，每人最多多1，奖项合计等于底池，仍只结算一次。

## Public test boundaries

- 在既有离线应用构造配置入口补充可控起点输入，复用固定牌序、手动时钟，通过公开命令及身份视图观察动作顺序、期限、底池和奖项。
- 用受控输入覆盖各候选、全押起点、空位和待局情景；不依赖随机重复抽中目标，不测试私有扫描结构或抽样调用次数。
- 通过HTTP／WebSocket验证多身份同步、重连后顺序及合法动作权限；浏览器观察当前行动与奖项。线上不提供选起点入口。
