# 04: 桌面与手机六座位布局及操作区

Status: done
Type: task
Blocked by: [01：五真人入房、开局与房主交接](01-five-human-room.md)
Spec: [升级规格](../spec.md) — U7、U8、U9、U10；UAC22、UAC24–25、UAC27（布局与操作部分）

**What to build:** 玩家在桌面和手机都能辨认六个固定位置、自身与当前行动者，并在明确的状态栏和“你的操作”区域完成入房、整局操作及下一局开局。保留现有深绿、金色及字体，桌面采用长椭圆牌桌。

## Acceptance criteria

- [x] UAC22：桌面真人3／4／5在上方从左到右，真人1左、真人2右、机器人下；切换观看身份不旋转座位，六席固定且空位标注“空位”，本人有“你”及高亮。
- [x] UAC24：每席按名称身份、两张手牌区域、筹码余额、本局投入与状态排列；房主、待局、断线、弃牌、全押标签清楚，当前行动突出且与本人高亮可同时辨认。空位和待局者不伪造手牌。
- [x] UAC25：上方状态栏显示阶段、当前行动、已有倒计时和连接提示，退出／重连入口位于上方；房满、接管、连接／唤醒、待确认和故障提示可见可用。
- [x] UAC25：机器人下方“你的操作”只显示本人合法动作，以及合条件房主开局按钮；下注／跟注实际扣款与不足全押明确，提交中和旧控制页权限继续受既定规则约束。
- [x] UAC27（本票部分）：390宽手机真人1／2第一行、3／4第二行、5第三行居中，机器人在公共区域下方；1280宽桌面遵循桌面位置。满席和空席均可纵向滚动完成操作，无页面横向溢出。
- [x] 状态与余额来自服务器确认视图，保持暗牌权限及既有合法按钮契约；若票03已完成，思考提示、计时依据和真人新期限显示必须保留，不由页面推定动作成功。

- 浏览器使用真实页面、身份和公开按钮，在390／1280宽观察五真人满席、空席、不同观看者、合法动作、连接异常和接管。
- 结合HTTP／WebSocket确认动作权限、实际扣款及身份裁剪；复用已完成容量票的公开行为测试，不以DOM隐藏代替服务端隐私裁剪。
