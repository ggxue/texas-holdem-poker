## Problem Statement

玩家需要更容易看懂的牌桌：牌型参考、公共牌、底池、各玩家手牌与筹码应当有明确位置，
电脑和手机都能完成操作并查看结算。当前三个并排信息卡片和文字牌面难以对应目标示意图。
玩家还希望同一房间最多容纳五个真人，每局随机选择行动起点，并让机器人表现出短暂思考，
使行动节奏接近真人，同时保持服务器状态、页面显示和真人行动期限一致。

原讨论先限定只改布局，用户随后明确增加容量、随机行动起点和机器人思考时序，
最后确认完整范围并要求将讨论发布为规格。规格发布阶段只记录需求；用户随后确认拆票并
授权连续实施，01–07已完成本地实现与验收。行为要求仍以本文为准，证据见上述链接。

## Solution

保留现有深绿、金色配色和字体，采用长椭圆牌桌、简洁牌面卡片及六个固定座位。
桌面左侧常驻十类牌型参考栏；真人3、4、5在上方，真人1在左、真人2在右、机器人在下。
中央底池位于横排五个公共牌位上方。手机将真人座位排列为两列三行，参考栏通过入口展开。
上方状态栏、下方“你的操作”和结算结果区保留完整可观察信息。

唯一房间最多五个真人，每局固定一个机器人，一至五个真人都可由房主手动开局。
每局从本局参赛者中等概率抽取一次行动起点，按真人1、2、3、4、5、机器人的循环顺序行动，
各下注轮和并列赢家的零头分配沿用该起点。
机器人每次合法行动独立等概率思考1–8整数秒，由服务器到期执行原有过牌／跟注策略。
界面显示从30秒按真实时间递减的模拟行动倒计时，实际思考结束即提前行动，
随后真人获得完整30秒行动期限。思考期间退出、重连、期限和提前结算照常处理。

### 规格优先级与覆盖范围

本规格与基线规格、内存决定共同组成升级后的目标契约；下列冲突以本规格为准。
旧票据和验收证据描述升级前的实际实现，不自动成为本规格的完成证据。

其余行为继续采用基线规格及当前内存决定：整数chips、底注1、固定下注10、四动作、
每轮一次主动下注、不足全押、单一底池、有效投入不退、牌型和花色比较、手牌隐私、
匿名身份与接管、房主交接、中途等待、断线宽限、内存筹码及成功重新入房设100。
不恢复数据库、重启恢复或已撤销AC。

## User Stories

1. 作为电脑玩家，我希望看到长椭圆牌桌，以便直观理解公共区域和玩家位置。
2. 作为已有玩家，我希望沿用现有配色和字体，以便改版后仍能熟悉地操作。
3. 作为真人1，我希望桌面座位始终在左侧，以便快速找到自己的信息。
4. 作为真人2，我希望桌面座位始终在右侧，以便观看者变化时位置仍稳定。
5. 作为真人3至5，我希望桌面座位在牌桌上方按编号排列，以便找到新增玩家。
6. 作为玩家，我希望机器人始终位于桌面牌桌下方，以便识别程序玩家。
7. 作为玩家，我希望六个座位的位置固定，以便人数变化时不必重新寻找玩家。
8. 作为玩家，我希望空位保留并标注“空位”，以便看出房间剩余容量。
9. 作为玩家，我希望自己的座位有“你”标签和高亮，以便在多人局中辨认本人。
10. 作为新手，我希望桌面左侧常驻十类牌型参考，以便随时对照牌力。
11. 作为新手，我希望参考栏按强到弱排列，以便理解既定牌型顺位。
12. 作为玩家，我希望每类牌型有五张简洁示例牌及中英文名称，以便辨识和对照。
13. 作为玩家，我希望手牌与公共牌呈现为简洁卡片，以便看清点数和花色。
14. 作为玩家，我希望公共牌区固定横排五个牌位，以便知道后续发牌位置。
15. 作为玩家，我希望未发公共牌显示空轮廓，以便区分未发牌位和已发牌。
16. 作为玩家，我希望底池显示在公共牌上方，以便同时查看牌面和待分配筹码。
17. 作为玩家，我希望金额明确标注为chips，以便理解它是游戏筹码。
18. 作为玩家，我希望每个座位按名称身份、手牌、筹码余额、投入状态排列，以便快速阅读。
19. 作为玩家，我希望房主、待局、断线、弃牌和全押以短标签显示，以便理解参与状态。
20. 作为玩家，我希望当前行动者突出显示，以便知道正在等待谁。
21. 作为玩家，我希望上方状态栏显示阶段、当前行动和倒计时，以便跟上牌局进度。
22. 作为玩家，我希望连接提示和退出／重连入口位于上方，以便发现异常并操作。
23. 作为玩家，我希望机器人座位下方有“你的操作”区域，以便辨认本人可执行的动作。
24. 作为玩家，我希望只出现本人合法动作并保留实际扣款说明，以便正确下注或跟注。
25. 作为房主，我希望开局按钮出现在操作区，以便结算后手动开始下一局。
26. 作为玩家，我希望操作栏下方直接展示结算结果，以便继续查看牌桌并核对奖项。
27. 作为玩家，我希望赢家和获得筹码突出显示，以便迅速识别结果。
28. 作为玩家，我希望按既定公开范围看到牌型、最佳五张、投入和结算余额，以便理解结算。
29. 作为玩家，我希望结果保留到下一局开始，以便有时间对照参考栏。
30. 作为手机玩家，我希望通过“牌型参考”入口展开参考栏，以便节省牌桌空间。
31. 作为手机玩家，我希望真人1／2、3／4分两行，真人5第三行居中，以便清晰阅读五个座位。
32. 作为手机玩家，我希望公共牌位保持一行且机器人在其下方，以便认出共同牌区。
33. 作为手机玩家，我希望状态、操作和结果纵向排列且页面能纵向滚动，以便完成整局。
34. 作为第五名真人，我希望能够入房占座，以便参与最多六人的牌局。
35. 作为第六名新真人，我希望收到房间已满提示，以便理解入房被拒原因。
36. 作为房主，我希望一至五名真人都能开局，以便无须等待房间满员。
37. 作为中途入房者，我希望仍按既定规则等待下一局，以便不继承其他人的本局资格。
38. 作为仍在房间的真人，我希望房主交接继续按最早入房顺序，以便扩容后权限仍正确。
39. 作为参赛者，我希望每局从所有参赛者中等概率选一次起点，以便起手座位轮换。
40. 作为玩家，我希望机器人也可以被选为起点，以便所有参赛者采用相同抽选范围。
41. 作为玩家，我希望各下注轮沿用同一循环顺序并跳过无行动资格者，以便预测行动次序。
42. 作为并列赢家，我希望零头沿本局循环顺序分配，以便顺序与行动一致且筹码守恒。
43. 作为玩家，我希望机器人每次合法行动前思考1–8秒，以便看到自然的行动节奏。
44. 作为玩家，我希望每次机器人行动机会独立抽取时长，以便每次等待长短可以不同。
45. 作为玩家，我希望刷新或重连不重新抽取起点或思考时长，以便已有进度保持稳定。
46. 作为玩家，我希望看到机器人“思考中”和30秒正常递减的倒计时，以便识别其等待状态。
47. 作为下一名真人，我希望机器人实际行动后才开始本人完整30秒，以便思考时间不占用本人期限。
48. 作为玩家，我希望思考期间仍能查询状态、退出和重连，以便房间继续响应。
49. 作为玩家，我希望触发提前结算时立即看到结果，以便不用等待已失效的机器人动作。
50. 作为玩家，我希望上一局迟到的机器人动作不能影响下一局，以便状态和筹码保持正确。
51. 作为玩家，我希望扩容和思考仍遵守既定暗牌权限与筹码规则，以便已有约定不被改版破坏。
52. 作为项目用户，我希望新增验收和旧完成证据明确区分，以便判断升级是否实际完成。

## Implementation Decisions

### U1：范围、模块与状态所有权

- 改动范围包括牌桌呈现、房间容量、行动起点、零头顺序、机器人实际思考与显示计时。
- 牌局模块统一拥有五个真人座位、固定机器人、本局参赛名单、起点、行动机会、思考和结算。
  时间与随机性由应用级显式配置seam提供；网络Adapter不自行推定动作、金额或起点。
- 所有有效状态变化仍在唯一进程中串行确认后通知页面；客户端只呈现按身份裁剪的确认视图。
  等待使用可取消的到期事件，房间在等待期间继续响应，不能持有状态更新锁休眠数秒。
- 不增加数据库、磁盘存档或跨实例共享；原内存与重连设100契约继续适用。

### U2：五真人容量与身份

- 唯一房间最多五个真人，固定真人1至5座位；新身份依次占第一个空位。
  第六个新真人拒绝入房并给房满提示，同身份接管不新增座位。
- 每局固定一个机器人，一至五个真人均可由房主开始；人数为2至6名参与者。
  按既定补给和底注规则处理每个本局参与者，不要求满员。
- 本局名单在开局时固定；中途入房者等待下一局，不继承同座位前身份的手牌、动作或领奖资格。
- 房主资格和交接沿用最早入房且仍在房间的真人，不按最低座位编号替代。
  例如后来填入真人1空位者不越过更早入房的真人2或3。
- 空位、本人标记、接管、退出、断线宽限及新局限制继续采用既有可观察行为。

### U3：每局随机行动起点

- 成功开局时从全部本局参赛者中等概率抽选一个Action Start Seat，包括机器人。
  空位和未参赛待局者不参与，已付底注全押的参赛者仍属于候选集合。
- 基础循环顺序为真人1、2、3、4、5、机器人再回真人1。
  每局只抽选一次，整局各下注轮从该起点按循环顺序查找可行动者。
  例如起点真人4时为真人4、真人5、机器人、真人1、真人2、真人3。
- 每轮跳过空位、未参赛、弃牌和全押者；起点无法行动时沿循环找到下一可行动者，
  不重新抽选起点。中途入房、退出、刷新或接管不改本局已有起点。
- 既有欠注应答保留：先过牌后有人下注者仍有跟注／弃牌机会，按同一循环顺序处理。
  已跟齐者不重复获得过牌机会，唯一能行动但欠注者仍先回应再进入既定Runout。
- 不随机打乱所有座位、不每轮重抽、不增加庄家或盲注。

### U4：零头分配

- 所有并列最强赢家先整数平分单一底池；零头从本局行动起点开始沿同一循环顺序分配。
- 只向并列赢家分配，跳过空位及非赢家，每人最多多得1 chip。
  例如起点真人4、底池21、真人4与真人1并列最强，分配为11和10。
- 仍按既定单池、全押争全池、投入不退及只结算一次规则执行；不另抽零头起点。

### U5：服务器机器人思考

- “出牌”在本规格中明确为机器人取得一次合法Check或Call行动机会。
  每次机会独立等概率抽取1、2、3、4、5、6、7、8秒；一次机会只抽一次。
- 服务器公布机器人当前行动／思考状态，保存此次机会的实际到期时间，
  到期仍有同局同机会的合法动作时执行既定策略：能过牌则过牌，否则跟注。
  策略不因时长、牌力或随机数改变，实际扣款和不足全押沿用既定规则。
- 同轮中机器人先过牌、随后需要回应下注时是新的行动机会，需要新的独立抽样。
  刷新、查询、重连、接管或无关的状态同步不是新机会，不重新抽样或延长期限。
- 机器人不需要行动的空位跳过、全押和自动补牌／结算流程沿既定规则立即推进，
  不人为给每张公共牌增加思考等待。
- 等待期间状态查询、退出、重连、连接宽限和其他已创建期限照常处理。
  离房触发唯一未弃牌者胜出时立即结算并取消旧机器人动作。
  其他使本次机会失效的变化也使旧到期事件无效，旧动作不能影响结束局或新局。
- 到期事件仍遵守原期限处理原则，包括同刻确认离房先于旧行动处理。
  下一名真人的30秒从机器人实际完成并进入真人行动机会时开始。

### U6：机器人30秒显示计时

- 机器人思考时突出其座位并显示“思考中”；上方显示从30秒开始按真实时间递减的
  模拟行动倒计时。它的真实动作期限仍为U5确定的1–8秒。
- 例如思考3秒，显示从30正常递减，约剩27秒时机器人完成动作；不把30到0压缩到3秒。
  之后切换为下一名真人完整30秒行动倒计时；如直接结算或切换到其他状态则显示该状态。
- 页面依服务器确认的思考开始时间／等价计时依据显示，刷新或重连不从30重新计时。
  模拟倒计时不是30秒机器人超时机会，不能因此让机器人自动弃牌或多等待30秒。
- 不使用网页动画延迟代替服务器实际等待，不让不同页面自行抽取时长或提前切换行动者。

### U7：桌面整体布局

- 沿用现有深绿、金色配色和字体，以原目标示意图确定长椭圆牌桌及区域关系。
- 左侧常驻完整十类牌型参考栏，按既有强弱顺序排列；每行包含五张简洁示例牌、
  中文名称与英文名称。中文采用项目现有术语，示例符合既定牌型定义。
- 六座位固定：真人3、4、5在牌桌上方从左到右横排；真人1在左、真人2在右、机器人在下。
  所有观看者看到相同位置，真人2观看时仍在右侧；空位保留，“你”标签及高亮标明本人。
- 中央底池在五个横排公共牌位上方；手牌和公共牌统一使用简洁卡片，
  已发公共牌显示点数与花色，未发牌位显示空轮廓。发牌仍遵循0、3、4、5的既定阶段。
- 金额以chips标注，示意图美元符号和示例数额不成为货币单位或实际状态。

### U8：座位信息、操作与结果

- 每座位按名称与身份、两张手牌、筹码图标及余额、本局投入与状态排列。
  有牌资格时显示两张牌面或牌背；空位和待局者显示对应状态，不伪造已发手牌。
- 房主、等待下一局、断线、弃牌、全押等使用短标签；突出当前行动者。
  本人高亮与当前行动标识可同时辨认。余额、投入和结果来自服务器确认状态。
- 上方状态栏显示阶段、当前行动、倒计时和连接提示，并放退出／重连入口。
  房满、接管、连接／唤醒、待确认和故障提示继续清楚可见。
- 机器人座位下方为“你的操作”，显示本人合法动作和符合条件的房主开局按钮。
  下注／跟注标明实际扣款和不足全押，提交等待及权限由原契约约束。
- 操作栏下方直接展示结果区，突出赢家和获得筹码，按既定公开范围展示牌型、
  Best Five、本局投入和结算余额，保留到下一局开始。
  Showdown、弃牌隐私及提前胜出不强制亮牌继续采用原规则。

### U9：手机布局

- 牌型参考栏通过“牌型参考”入口展开，包含与桌面同样的十类内容。
- 五个真人座位位于公共牌上方：真人1／2第一行，真人3／4第二行，真人5第三行居中。
  六个位置固定，空位保留，机器人仍在公共牌下方。
- 公共牌五个牌位保持一行；状态、操作、结果按既定关系纵向排列，页面可纵向滚动。
  内容与按钮可读可用，不能为了保留桌面横向关系把操作区域缩到不可用。
- 具体响应式阈值、字号、间距和卡片尺寸为例行实现选择，须满足桌面／手机验收。

### U10：公共交互契约

| 输入或事件 | 必须可观察的输出 |
| --- | --- |
| 入房／接管 | 五真人容量内正确占座或同身份接管，身份视图不泄漏其他玩家暗牌；满房明确提示 |
| 合法开局 | 固定参赛名单、既定补给与底注、一次随机行动起点；返回确认牌局和当前行动／思考状态 |
| 合法真人动作 | 沿本局循环顺序推进；轮到机器人时公布思考状态而非立即执行；实际筹码与请求幂等性沿用原契约 |
| 机器人思考到期 | 机会仍有效则执行一次合法动作并推送新状态；真人下一机会此时开始完整30秒 |
| 等待期间退出／期限 | 原离房、计时、提前结算规则照常生效；失效机器人动作不再改变状态 |
| 刷新／重连／接管 | 返回当前确认状态和原有计时依据，不重新抽起点或时长；本人余额仍按既定成功重新入房设100 |
| 结算 | 按当前公开范围展示结果，以本局循环顺序分零头，并保留至下一局 |

以上是行为Interface，不指定路由、JSON字段名、Go签名、私有数据结构或定时器数量。

## Testing Decisions

### 已确认的公开测试范围

- 沿用基线Q28已确认的牌局命令→按身份可见状态主seam；HTTP／WebSocket集成观察
  身份、控制权、消息权限、并发与真实推送；浏览器操作验证布局、计时文字和整局交互。
  本次不再次访谈既定测试范围。
- 复用已有固定牌序和可控时钟，在同一应用构造配置seam补充可控随机起点与思考时长输入。
  这些只供离线测试，线上HTTP／WebSocket不提供选座起点、选时长、改牌或改筹码入口。
  不为每个私有辅助函数增加测试入口。
- 以公开输入、动作顺序、消息、余额、底池、期限和浏览器可见内容断言行为。
  不断言数组长度实现、私有字段、锁布局、函数调用次数或定时器数量。
- 随机等概率是生产策略要求；测试通过受控输入覆盖各候选及1／8秒边界，
  不靠随机重复运行碰出案例或统计抽样偶然通过。不以“各候选可强制选到”替代对等概率策略的审阅。
- 时间测试使用现有手动时钟，期待结果来自下面固定案例和手算；不sleep数秒或30秒等待。
  必须观察到期前不行动、到期后只执行一次、刷新不改变原时间等外部结果。
- 先例为现有入房、牌局、下注、房主交接、接管与期限集成测试，以及浏览器烟测脚本。
  浏览器使用真实页面和公开按钮验证，不增加在线fixture控制入口。
- 实施时按票TDD与Standards／Spec双轴审查；需要可复现Go检查、并发race及浏览器证据。
  当前发布只做文档Harness与格式／链接校验，不把它们当游戏验收。

### 可追踪验收案例

本规格使用独立UAC编号，不改写旧票据历史证据。UAC01–28已通过记录的本地自动化与
浏览器路径，逐项回链见[升级验收证据](acceptance-evidence.md)；真实手机、其他浏览器及真实云限制见该页末节。
旧AC中未被覆盖的规则仍需回归；下表特定余额和牌序仅用于离线fixture。

| ID | 输入或触发 | 必须可观察的结果 |
| --- | --- | --- |
| UAC01 | 五个新真人依次入房，再来第六个新真人 | 前五位占真人1–5，第一位为房主，第六位被拒且房满；不抢占座位 |
| UAC02 | 分别以1、2、3、4、5真人由房主开局 | 每局固定一个机器人，每人两张手牌；首次各100扣底注后99，底池分别2、3、4、5、6；不要求满员 |
| UAC03 | 五真人房满时同身份新页接管，旧页发动作／关闭 | 不多占座位，旧页无权且不让新页离房；本局起点与已有思考时间保持，成功重新入房仍设100 |
| UAC04 | 局中在空席加入新身份或重用已离房座位 | 仅看公开状态并等待下一局，不继承手牌、动作、领奖资格；该局起点不重抽 |
| UAC05 | 真人1／2／3依次入房，1退出后新玩家填1号位，随后真人2退出 | 房主交给原真人3，不交给后来填1号位者；按最早入房顺序而非最低座位号交接 |
| UAC06 | 六人局受控抽中真人4，依次无人下注过牌并进入下一轮 | 各轮顺序为4、5、机器人、1、2、3；每局起点只确定一次，各轮不重抽 |
| UAC07 | 受控抽中机器人，或只有部分真人参赛 | 机器人可成为起点；候选只含本局参赛者，空位／待局者不参与；循环跳过空席 |
| UAC08 | 抽中底注后全押者，或后续轮起点玩家已弃牌／离房 | 起点保持，按循环跳过无法行动者，仍按既定欠注／Runout／提前胜出推进 |
| UAC09 | 起点真人4，真人4先Check、真人5Bet10，其他可行动者回应 | 真人4随后按循环获得Call／Fold；已跟齐者不重复行动，不能跳过欠注者 |
| UAC10 | 一局中刷新、重连、接管，随后进入新下注轮 | 当前本局起点、循环顺序和行动期限保持；重连筹码另按既定内存决定 |
| UAC11 | 起点真人4，底池21，真人4与真人1共用最强五张，其余人已弃牌 | 真人4得11、真人1得10，其他人0；不退投入、不增发、不向非赢家分零头 |
| UAC12 | 起点为非赢家或已离房者，多个并列最强赢家且有零头 | 沿同一循环跳过非赢家，仅赢家获零头，每人最多多1，合计等于底池 |
| UAC13 | 机器人无需跟注，受控思考1秒 | 到期前仍是机器人思考且未过牌；1秒到期执行一次Check，按规则推进 |
| UAC14 | 机器人需跟10，受控思考8秒；分别余额足够和仅剩4 | 到期前余额和投入不变，8秒时分别Call10或Call4全押；没有随机策略、Bet或Fold |
| UAC15 | 同轮机器人先Check，之后真人Bet10，机器人再次取得Call机会 | 两次机会分别独立抽样；第一次时长不复用于第二次，同次查询不触发新抽样 |
| UAC16 | 机器人正在思考，刷新／重连／接管或重复请求状态 | 沿用原实际到期时间与显示计时依据，不重新抽样；动作只执行一次 |
| UAC17 | 机器人思考3秒，下一可行动者是真人 | 界面从30按真实秒递减，约剩27时机器人行动；此时真人新期限是完整30秒 |
| UAC18 | 机器人思考中查询状态、退出、重连或连接宽限到期 | 这些请求／事件照常处理，不能等机器人思考结束才响应；状态仍一致并按身份裁剪 |
| UAC19 | 机器人思考中其他最后一名未弃牌真人确认离房 | 按既定规则立即给唯一未弃牌机器人结算，无需等思考到期；原定动作失效且不重复派奖 |
| UAC20 | 旧思考事件在结算后或下一局开始后迟到；离房与思考到期同刻 | 不改变已结束局／新局；同刻先确认离房，再仅处理仍有效的动作 |
| UAC21 | 机器人已全押、无需动作而Runout，或唯一未弃牌者提前胜出 | 按既定流程补齐／结算，不为自动发牌或无行动机会增加思考时间 |
| UAC22 | 六席桌面由真人1、2及其他身份分别观看，含空位 | 3／4／5上方，1左、2右、机器人下；观看者变化不旋转，本人有“你”及高亮，空位保留 |
| UAC23 | 桌面查看参考栏、公共牌和余额，覆盖翻牌前到河牌 | 十类强到弱、五张示例牌及中英文名完整；底池在五牌位上方，空轮廓逐步变为牌面，单位chips |
| UAC24 | 观察房主、待局、断线、弃牌、全押及当前行动者 | 座位信息层级正确、标签清楚；本人高亮与当前行动／思考标识均可识别 |
| UAC25 | 非本人回合、本人合法动作、短额全押、房主开局及连接异常 | 状态栏和退出／重连可用；“你的操作”只显示合法动作与合条件开局，实际扣款及不足全押明确；满房／接管／连接／故障提示清楚 |
| UAC26 | 摊牌与提前胜出，查看结果后等待下一局 | 操作栏下方突出赢家与获奖，按既定权限显示牌型、Best Five、投入和结算余额；提前胜出不强制亮牌，下一局前保留结果 |

## Out of Scope

- 除本次容量、起点、零头顺序和机器人时序外，改变既定扑克与筹码规则。
- 大厅、多房间、超过五个真人、多个机器人、机器人自行开局、动态旋转座位。
- 新增盲注、庄家、加注、自由金额、独立全押按钮、主池／边池或退款规则。
- 按牌力决定机器人时长或策略、胜率分析、诈唬及随机选择动作。
- 精细牌面插画、额外动画、音效、聊天、昵称账号、排行榜和历史回放。
- 数据库、持久筹码、重启恢复、跨进程共享或额外云资源；旧撤销范围不恢复。
- 规格发布阶段只记录需求；后续用户授权的七票实施、验证与本地提交已独立完成，云部署仍不在本批范围。
