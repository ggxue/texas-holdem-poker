# 本局记录 C 与筹码动效 A

Status: ready-for-agent
Type: spec
Decision status: agreed
Baseline: `7d375e357d31faf550b91ab61e393a63ebf3fcd0`

## Problem Statement

玩家只能看最终结算，难以理解本局每个人做过什么；筹码转移只有数字变化，缺少投入与收池的刺激感。
用户已选择 C · 按阶段展开的本局记录和 A · 弧线抛注，要求自动完成规格、票据、实施与本地提交。

## Solution

将结果区升级为“本局”，默认按阶段呈现从开局到派奖的完整公开过程，并保留结算标签。
服务器保留本局确认记录，刷新、重连与中途入房都可恢复；每一步金额保持当时快照。
实际投入沿实体筹码弧线飞向底池，派奖先聚拢再成束飞向赢家，金额和操作即时更新。

## User Stories

1. 作为玩家，我希望看到开局与固定参赛名单，以便理解这一局是谁参与。
2. 作为玩家，我希望看到每个人的底注，以便理解初始底池。
3. 作为玩家，我希望知道私人手牌已发出，以便理解流程而不泄漏别人的牌。
4. 作为玩家，我希望看到翻牌、转牌、河牌与当时公共牌，以便定位行动阶段。
5. 作为玩家，我希望看到所有玩家与机器人的每一步行动，以便追踪局势。
6. 作为玩家，我希望看到实际投入金额，以便区分完整跟注和不足额跟注。
7. 作为玩家，我希望知道过牌与弃牌没有扣款，以便正确理解零金额。
8. 作为玩家，我希望看见主动全押及跟注后全押，以便理解后续资格。
9. 作为玩家，我希望看到每一步之后的底池和行动者余额，以便核对筹码。
10. 作为玩家，我希望看到顺序与发生时间，以便理解先后。
11. 作为玩家，我希望超时动作注明自动原因，以便知道谁实际作了决定。
12. 作为玩家，我希望机器人动作注明原因，以便理解机器人的参与。
13. 作为玩家，我希望看到断线、返回、离房与离房导致的弃牌，以便理解跳过行动和资格变化。
14. 作为玩家，我希望看到重连设100与开局前补给，以便解释钱包变化。
15. 作为玩家，我希望历史快照保持原值，以便重连不会改写已发生的投入。
16. 作为玩家，我希望记录绑定原参赛者身份，以便新占同一座位的人不会继承旧行动。
17. 作为玩家，我希望看到摊牌、结算与每位赢家奖项，以便解释最终结果。
18. 作为玩家，我希望按阶段展开过程，以便快速定位长局中的步骤。
19. 作为玩家，我希望当前阶段默认展开，以便看到最新进展。
20. 作为玩家，我希望底部跟随新记录，以便实时查看。
21. 作为玩家，我希望回看时不抢滚动，以便读完之前的内容。
22. 作为玩家，我希望有新记录提示与回到最新入口，以便主动恢复跟随。
23. 作为手机玩家，我希望“本局”详情包含过程和结算，以便操作区仍常驻。
24. 作为桌面玩家，我希望完整六人结算仍一屏可读，以便方便核对结果。
25. 作为刷新或返回玩家，我希望恢复本局公开过程，以便了解先前发生的事。
26. 作为中途加入者，我希望了解当前局公开历史，以便等待下一局。
27. 作为玩家，我希望下一局替换旧过程，以便不把两局混在一起。
28. 作为玩家，我希望重复或失败请求不制造记录，以便记录可信。
29. 作为玩家，我希望实际底注、下注、跟注和全押有筹码飞行，以便投入更有感觉。
30. 作为玩家，我希望余额为0的全押也能发射筹码，以便动画完整。
31. 作为赢家，我希望整池聚拢并飞回自己，以便有明显获胜反馈。
32. 作为平局赢家，我希望按实际奖项分束收池并显示+金额，以便零头准确。
33. 作为观看者，我希望看见其他人的投入和收池，以便追踪流向。
34. 作为玩家，我希望数字、倒计时和合法动作立即更新，以便动画不影响操作。
35. 作为玩家，我希望连续动作加速和重叠而不积成长队，以便看到当前局势。
36. 作为玩家，我希望最后投入先到池再收池，以便视觉因果清楚。
37. 作为手机玩家，我希望动画减量且不盖住详情，以便画面可读。
38. 作为玩家，我希望关闭动画并记住偏好，以便按自己的习惯游玩。
39. 作为减少动态用户，我希望只有静态金额提示，以便舒适使用。
40. 作为玩家，我希望刷新、重连、后台返回及回看不补旧动画或声音，以便不误认为新行动。
41. 作为玩家，我希望布局变化清理错位动画，以便筹码不会落错位置。
42. 作为玩家，我希望保留既有声音和规则，以便更新不会改变玩法。

## Implementation Decisions

- 当前局由服务器保留按顺序追加的公开记录，与余额、资格、机会和公告共同成功提交或回滚。
  记录只属于当前局，下一次成功开局替换；失败开局保留旧局。进程重启清空，不新增磁盘或数据库。
- 记录包含稳定事件标识、局标识、局内顺序、服务器时间、阶段、种类、原参与者身份和座位、
  动作、实际金额、全押及自动原因、动作后底池与参与者余额；阶段只包含已经公开的公共牌。
  新金额字段以精确十进制字符串提供，不从浮点差值猜测；不包含私人手牌或未来牌序。
- 开局、补给、逐人底注、发手牌、三轮公共牌、所有有效动作、摊牌（发生时）、结算、逐人派奖均记录。
  断线、返回、入房／钱包设100、离房与离房弃牌也记录；身份与开局参赛资格分开。
  无牌局时不创建历史；同控制连接直接恢复不设钱包100，但记录返回。
- 当前查询和成功 WebSocket 初始视图包含本局完整公开过程。原瞬时语音公告继续不回放历史。
  HTTP 与 WebSocket 的同次确认使用相同记录标识；重复请求、拒绝与回滚不追加成功记录。
- C 结构为按阶段分组的可展开章节，当前新阶段默认展开；已手动展开／收起的章节在同局保留。
  条目旧→新，金额使用历史快照。原参赛者与当前同席新人有明确归属提示。
- 桌面右栏与手机原结果入口改为“本局”，过程／结算标签默认过程。
  新过程可以内部滚动，回看保持位置，新条目提示并可回到最新；切回过程保持回看／跟随状态。
  下一局清理旧展开与未读状态。结算沿用允许公开的牌型、最佳五张和完整参赛者结果。
- 保留 B2、紧凑六席、本人／行动者标记、手机常驻操作和触控尺寸。
  1280×720 满员结算无页面／结算内部滚动；360×640 及390×720牌桌无需滚动，320×568可局部滚动。
- A 动效采用金／红／白实体筹码弧线、错峰、短促落点反馈。底注同批同时汇入；普通投入约300–450ms，
  全押约500–650ms，收池先聚拢再成束约800–1000ms。筹码数量分档封顶，只示意规模。
- 动效读取确认记录和原参赛者身份；真实金额、底池清零、合法动作与倒计时先更新。
  独立且不拦截点击的动画层低于手机详情与操作，余额0也保留发射定位。
  单赢家收全部视觉池；多人平局按服务器金额分束，包含既有零头顺序，显示各自+金额。
  无法定位原身份时取消对应飞行，不飞向同席新人；记录与结算仍准确。
- 动效可短暂重叠／加速，最后投入尽量先落池再派奖，限制同时飞行与积压时长。
  记录始终完整，过牌／弃牌／补给／钱包重置不生成投入飞行。
  新局只播放该局实时确认的底注，不播放上一局残留；刷新、重连、后台返回、回看不补旧动效。
- 默认开启动效开关，记住本浏览器偏好；存储受限时当前页仍可操作。
  尊重系统减少动态，转为静态金额提示；关闭动效仍正常更新游戏。
  详情遮挡时跳过飞行、不自动收详情；旋转、窗口变化、牌桌滚动、后台及断线清理残留。
- 不新增筹码声音；现有中文播报、提醒、静音、优先级与恢复规则沿用。
  保留单底池、小投入可赢全池、无退款、主动全押及重新应答规则、筹码只存内存与重连设100。

## Testing Decisions

- 用户要求一条龙完成，沿用此前已确认的公开测试 seams：真实命令→身份裁剪的 HTTP／WebSocket 视图，
  以及真实浏览器页面的可观察交互。无需重复访谈，不新增私有结构测试或在线作弊入口。
- 固定牌序、余额、时钟和起点只使用已有离线构造／fixture先例。预期为下面独立案例，
  断言公开记录、公开视图与可见页面，不抄实现公式或检查私有协作者调用顺序。
- 每票 red→green；金额与回滚通过公开传输验证，呈现／跟随／动画与偏好通过浏览器验证。
  复用既有 HTTP 游戏、公告、超时、真实浏览器与手机验收先例。末尾运行 Harness、格式、vet、全套测试、构建和 race。

| HRC02 | 玩家1下注10，玩家2跟注，机器人跟注 | 实际10；底池13/23/33，余额89；翻牌只有前三张公共牌 |

| HRC05 | 重试、非法动作、机会随机源失败或派奖溢出 | 记录身份和内容不重复；失败记录／金额／机会共同回滚 |

| HRC07 | 离房后同席新人加入 | 原身份行动与离房弃牌不归新人，新人不可获得旧手牌或获奖动画 |
| HRC08 | 超时、断线及直接控制连接恢复 | 自动原因正确，直接恢复不设100，不修改旧期限；离房资格正确 |
| HRC09 | 结束、成功下一局、失败下一局、重启 | 保留到成功新局才替换；归零补给在新局底注前；重启无旧记录 |
| HRC10 | 回看时有新记录、切标签、手机详情 | 不抢位置、提示未读、可恢复跟随；C结构与完整结算可读 |
| CMA01 | 新确认底注、下注／跟注／全押 | 全部参与者包括机器人按实际金额飞行，0余额可发射；不挡操作 |
| CMA02 | 单赢家、多人平局以及最后跟注导致结算 | 数字即时更新，整池聚拢、正确分束、+精确金额；末次投入先入池 |
| CMA03 | HTTP／WS重复、旧响应、刷新／重连／后台恢复／回看 | 同事件最多播放一次，无旧飞行或旧声音补播 |
| CMA04 | 密集事件、手机、详情遮挡、旋转／滚动 | 飞行数与时间封顶；详情保持、无越层飞行、清理残留，无落错新人 |
| CMA05 | 关闭、刷新、减少动态系统偏好、存储受限 | 偏好持久；关闭无飞行；减少动态静态金额，游戏更新和操作正常 |
