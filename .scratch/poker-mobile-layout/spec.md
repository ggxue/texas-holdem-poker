## Problem Statement

用户真机试玩发现，手机页面的顶栏、座位与公共区纵向占据过多空间，首屏无法看清牌桌，
轮到本人时还需要向下滑很长距离才能找到操作。桌面 UI 已获用户确认，无需重新设计。
此前“手机无横向溢出、允许纵向查看”的检查没有覆盖行动是否立即可见。

## Solution

手机采用用户选定的 A · 紧凑六席：保留六席的固定空间关系、中央公共牌和独立底池，
本人手牌、本人标记及行动者标记清楚可辨。底部固定显示当前行动提示与合法操作；
玩家详情、完整结算和说明按需展开，详情不遮挡操作。

以浏览器实际可用的 CSS 视口为准，宽至少360px、高至少640px的常见手机竖屏，
六席、公共牌、底池、本人手牌及操作区应首屏可见。320×568这类极矮视口接受牌桌
少量局部滚动，行动提示和按钮始终可见。通过紧凑排布和详情分层实现，不用全页缩小
或长页面滚动寻找行动。桌面保持既有 B2 布局。

## User Stories

1. 作为手机玩家，我希望打开页面即可看到紧凑六席，以便了解全桌局面。
2. 作为手机玩家，我希望六席保持固定空间关系，以便持续找到同一玩家。
3. 作为手机玩家，我希望本人座位不随身份旋转，以便避免误认座位。
4. 作为手机玩家，我希望看到公共牌与底池，以便判断当前局面。
5. 作为手机玩家，我希望看到本人两张私人手牌，以便决定行动。
6. 作为手机玩家，我希望“你”和本人暖金标记保留，以便快速定位本人。
7. 作为手机玩家，我希望行动者的象牙白标记和状态文字保留，以便看清轮到谁。
8. 作为当前行动者，我希望本人和行动者两种标记同时可见，以便确认轮到自己。
9. 作为手机玩家，我希望行动提示与按钮固定可见，以便无需下滑很长距离寻找操作。
10. 作为小屏手机玩家，我希望仅牌桌可少量滚动，以便按钮不随长页面离开视口。
11. 作为手机玩家，我希望只看到服务端允许的动作，以便不会提交无效行动。
12. 作为手机玩家，我希望下注、跟注、全押的实际金额保持准确可读，以便知道扣款。
13. 作为短额玩家，我希望同额跟注与全押仍按现有合法动作显示，以便继续采用已确认的规则。
14. 作为提交动作的玩家，我希望待确认提示可见且按钮禁用，以便不误认为已经成功或重复提交。
15. 作为手机玩家，我希望过牌与弃牌同样容易点击，以便选择正确动作。
16. 作为等待中的玩家，我希望当前行动者、机器人思考与剩余时间可见，以便跟上进程。
17. 作为手机玩家，我希望通过详情查看各席完整信息，以便紧凑牌桌不丢失重要数据。
18. 作为手机玩家，我希望完整结算可展开查看全部六人的结果，以便核对赢家、派奖与最佳五张。
19. 作为手机玩家，我希望牌型参考和说明按需查看，以便不挤占牌桌首屏。
20. 作为手机玩家，我希望展开详情时行动区仍可见，以便不错过当前机会。
21. 作为手机玩家，我希望关闭详情后回到原牌桌，以便继续观察对局。
22. 作为手机玩家，我希望声音开关、音量、恢复声音、重连和退出仍可访问，以便继续使用原有功能。
23. 作为断线或被接管的玩家，我希望相关状态与恢复入口清楚可见，以便不会把不可用按钮当成有效机会。
24. 作为重入房间的玩家，我希望余额设100与原全押状态正确呈现，以便不误解参与资格。
25. 作为手机玩家，我希望空席和断线席保留准确的状态，以便看清房间情况。
26. 作为手机玩家，我希望实体筹码与准确可用筹码、投入分开呈现，以便不会混淆余额和下注。
27. 作为手机玩家，我希望看不到其他玩家未公开的私人手牌，以便保持隐私。
28. 作为手机玩家，我希望按需展开的信息可以滚动读完且无横向溢出，以便核对完整内容。
29. 作为桌面玩家，我希望既有 B2 一屏布局保持原状，以便延续已确认的使用体验。
30. 作为玩家，我希望正式页面没有原型选择器或模拟场景，以便操作真实对局。

## Implementation Decisions

- 采用原型 A 的手机信息结构及完整交互方向，保留深红赌场主题、桌沿席位、纸牌、实体筹码、
  固定身份、“你”标记和行动者标记。B、C 不作为生产页面的可选模式。
- 常见手机竖屏优先显示六席、公共牌、独立底池、本人手牌、当前行动状态与底部操作区。
  宽度360px以上且高度640px以上的手机布局不得要求滚动后才能看清这些核心信息。
  尺寸指实际内容视口，浏览器地址栏等占用不计入；使用100%页面缩放。
- 320×568作为极矮手机验收样例，允许牌桌少量局部滚动。底部行动提示与合法按钮始终在可见
  视口内，不与牌桌一起滚走。原型约68px滚动是参考证据，不是正式版必须复制的像素数。
- 固定操作区包含当前机会及提交反馈，避免被牌桌、详情或设备底部安全区域遮住；为它预留
  内容空间，不能以覆盖手牌或席位来满足可见性。按钮保留明确文案与可点区域。
- 玩家详情、完整结算、牌型参考及其他说明按需展开；完整内容可在详情区域滚动查看。
  展开和关闭只改变呈现，不发送牌局动作、不改变身份、不创建新行动机会或重置期限。
  详情不得遮挡固定行动提示与按钮；关闭后继续显示当前真实状态。
- 紧凑顶栏提供玩家、结果及更多功能入口。原有声音控制、恢复声音、重连、退出及内存规则
  说明仍能访问；移动这些控件不得改变其语义、默认值、偏好记忆或连接行为。
- 正式版移除原型审阅底栏、A/B/C切换、场景选择、模拟动作与电脑手机画框。
  原型用于说明设计，正式页面继续由真实身份裁剪状态、HTTP/WebSocket及现有状态更新驱动。
- 操作仍只来自服务端合法动作；准确金额、全押资格、提交禁用、错误、重连、控制页接管
  继续遵循现有契约。不从紧凑布局推断额外合法动作或自行计算扣款。
- 私人手牌、公开牌及最佳五张保持原有可见性；详情不能通过展开泄露尚未公开的信息。
  空席无虚假手牌或筹码，余额零、弃牌、等待下一局、断线、重入后的表现沿用既有规则。
- 牌局播报、行动提醒与服务器计时保持原状；展开详情不重复播报或干扰去重、静音与恢复。
- 桌面继续保持1280×720及以上既有 B2 一屏布局、完整六人结算、牌型参考、控件与字号要求。
  本轮只改变手机呈现，不附带会话协调或服务端提交协议的架构重构。
- 不改变后端API、筹码模型、权威状态或存储模式。本轮没有新增领域词汇或需要ADR的架构决定。

## Testing Decisions

- 沿用已确认的最高公共边界：真实浏览器操作真实页面，观察公开HTTP/WebSocket状态与反馈。
  本轮不新增私有函数、DOM构造方式或CSS类名的测试边界，不增加在线作弊或预设赢家入口。
- 以最终可见内容、按钮可点性、准确金额、禁用状态、信息完整性和布局几何为断言，
  不以“用了固定定位”或“存在某个类名”代替用户结果。期望来自本规格和既有规则。
- 复用现有浏览器烟测、全押浏览器检查与HTTP/WebSocket集成测试的先例；需要可重复场景时
  沿用既有离线时钟、牌序、起点和余额构造。生产验收不能用原型固定快照替代。
- 手机核心布局在360×640、390×720、412×780检查；320×568检查局部滚动边界。
  同时检查1280×720与更宽桌面。尺寸均为CSS视口、100%缩放，检查实际截图及几何，
  不能仅凭无横向溢出判定通过。主要游戏按钮的可点击高度至少44px。
- 本人采用玩家1及玩家4视角验证固定席位。覆盖满员本人行动、短额动作、待确认、机器人思考、
  空席、六人结算、重入100仍全押与断线/接管；前端缩排不得改动这些状态的公开结果。
- 原型已完成33个尺寸/场景检查，是设计证据，不是正式版本通过记录。
  正式实现先复现旧页面的行动不可见问题，再验证改进及回归；保存输入、截图、结果与限制。

## Out of Scope

重新设计桌面或赌场主题；旋转座位；新增扑克规则、边池、退款、自由金额或机器人策略；
修改主动全押、跟注不足、重新开放行动、计时、声音和提醒规则；账户、数据库、持久化或
重连恢复保证；上线原型工具；为布局修复附带架构重构；自动部署或创建云资源。

本规格不承诺所有任意矮屏都完全无滚动，也不把浏览器模拟、本地检查或用户试玩当成
所有手机、浏览器及完整公网验收。旧云端验收票状态须依据独立记录，不能因本规格就标记完成。

## Further Notes

用户先选择 A · 紧凑六席，随后对两个问题答复“都同意”：常见360×640起核心信息首屏可见、
320×568类矮屏允许局部牌桌滚动且行动常驻；沿用固定操作区、按需详情并移除审阅栏。
公共测试边界与既有规则也已经明确，不需重复访谈。本文件是已确认决定的综合，规划不等于实施。

本规格覆盖旧B2手机两列纵向排布及旧全押规格仅要求手机可纵向查看的布局要求；
其余游戏、桌面、声音、内存和隐私要求继续有效。本次只发布本地规格；尚未分实施票、
改动正式游戏或部署。真正实施前记录当时基线，按票验证并分别审查Standards与Spec。

原 improve-codebase-architecture 的探索与HTML报告保留，候选选择和设计讨论仍待进行。
手机布局修复优先推进，不把架构候选默认为已选择或已实施。
