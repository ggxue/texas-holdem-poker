## 已核对事实与可行路径

完整官方资料与取舍见[研究记录](research.md)。首选少量现有筹码 SVG 配合原生
Web Animations API，主要动画化 transform/opacity。这是针对本项目的工程建议，
不是业界唯一最佳方案；没有实机帧率、功耗或 Safari 验收结论。

- `chips.js:4`：现有筹码堆按规模分档并封顶，精确金额由数字表达；余额为 0 时无 SVG。
  钱包容器仍在（`app.js:174–179`），可以保留几何或模板作为动画发射点。
- `game.go:451–457`：确认扣款后发布 action，实际金额为十进制字符串，机器人走同一规则。
  金额 0 的过牌／弃牌不能表现成真实投入。
- `commands.go:130–135`：HTTP 与 WebSocket 可以带同一事件编号；必须去重。
  当前查询、新连接不补历史（`announcements.go:32`、`socket.go:165`），
  可借鉴 `voice.js:139–158` 的恢复边界，但动效无需等待语音队列。
- `game.go:370–385`：结算、全部 winner 事件、入账、底池清零在同次成功提交中发生。
  最终页面上可能已无底池堆；临时视觉堆可由同局 winner 的实际奖项合计表达，
  不能为了等动画而延迟权威余额、期限或合法动作。
- `game.go:347–378`：多人平局各有奖项，零头已按固定起点分配。
  直接采用每位赢家实际金额；不是所有局都只有一个赢家。
- announcement 当前只有 seat，没有参与者 ID。应匹配 handID 的原参赛名单；
  旧动画不能落到后来占同席的新人。原参赛者保留、离房释放座位（`game.go:475,493`）。
- `app.js:74–91,125`：底池和席位每次重建。独立动画层才不会被重绘移除。
- `game.go:191–202`：底注没有独立确认事件。若选择底注动画，可与本局记录的底注事件一起补齐，
  不能用钱包差值猜，因为还存在补给与重连设100。
- 手机详情会覆盖牌桌并克隆席位（`mobile.js:38`）；端点必须指向 `#seats` 的原牌桌，
  遮挡、滚动及旋转时清理或重测，不指向详情中的副本。

## 已确认范围（七项全部按推荐）

七项可独立决定，均以现有权威游戏规则继续有效为前提。

1. **覆盖范围**：全部参与者（包括机器人）实际投入的底注、下注、跟注、全押以及派奖。
   过牌／弃牌不飞筹码，筹码补给／重连重置不表现成下注。底注可以六席同时汇入。
2. **确认与金额时机**：服务器确认后才播放；数字余额、底池、结算及合法操作立即更新。
   飞行与临时视觉底池只表示已经发生的转移，不挡操作、不等待动画才开始下一机会。
3. **视觉风格**：沿用金／红／白实体筹码，弧线抛出、错峰与短促落点反馈。
   普通投入约300–450ms；全押更密集约500–650ms；派奖收拢后整束涌向赢家约800–1000ms。
   数量随金额分档并封顶，不逐枚对应金额；不晃整个牌桌。时长为待原型选择的起点。
4. **密集动作与过期**：短队列可重叠／加速，尽量保持最后投入先入池再派奖。
   短时间多条消息不排成长动画；积压时压缩旧动效，完整事实仍保留在本局记录。
   新局、刷新、重连、后台返回不补旧动画；回看本局过程不触发动效重放。
5. **赢家表现**：单赢家收走全部视觉底池；平局按服务端实际奖项分为几束，同时飞向各赢家，
   落点显示各自 +金额。所有观看者都能看到，不只显示本人获奖。无法安全定位原参赛者时，
   保留准确结果提示，取消该落点的飞行，不给新占座者制造获奖效果。
6. **手机与关闭**：手机保留相同两类动效，减少同时飞行数量；详情遮住牌桌时不在详情上飞，
   保留记录／结果，不强行收起详情。提供默认开启的动效开关，记住本浏览器偏好；
   系统要求减少动态效果时改为静态金额提示。布局变化时取消错位的残留动效。
7. **声音范围**：首轮仅画面动效，沿用现有中文播报与提醒，不新增筹码音效。
   若用户希望加声音，再讨论音色、混音、静音与优先级。

## 设计树

目标：让已发生的投入与派奖有刺激、可读的视觉表达。

1. 事实前提：现有事件与筹码坐标能否准确表示这两种流向？官方浏览器机制是否适合？
2. 事实已满足前提，七项范围已获确认；下一前沿为动效原型的视觉选择。
3. 若用户改变前沿推荐，重新计算依赖问题；动效原型已获授权，视觉方案仍待审阅。
