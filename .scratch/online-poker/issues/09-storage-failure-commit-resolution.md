# 09: 存档不可用与提交结果不明

Status: ready-for-agent
Type: implementation
Spec: [在线德州扑克首版规格](../spec.md)
Blocked by: [05](05-balance-refill.md)、[08](08-disconnect-action-timers.md)
Primary acceptance cases: AC34–AC35

## What to build

存档故障时页面显示恢复中/结果待确认并停止全部状态变更；提交响应丢失后先核对原请求结果，重试不会重复扣款、派奖、补给或收底注。

## Acceptance criteria

- [ ] 真实PostgreSQL复现提交前失败、成功后丢响应与原事务尚未结束的情况；余额/池/状态只完整提交或不变。
- [ ] 相同稳定请求标识只产生一次效果，同标识不同内容拒绝；不能因暂时无记录就重复执行仍未结束的事务。
- [ ] 结果不明期间不报告成功或再次扣款，恢复后查询权威结果，按已提交结果回应或在确认原事务结束后重新验证同请求。
- [ ] 玩家、机器人、计时、离房、补给、发牌和结算均停止未提交变化；存档不可用拒绝新开局。
- [ ] 恢复后重新读取存档，先解决待确认结果再继续，不用旧内存续写；仅数据库故障且连接仍在不额外给连接宽限（AC38相关子场景）。
- [ ] 页面展示最后确认视图时注明可能过时，结果待确认明确，前端不能自行记账；重试返回内容按当前身份权限裁剪。

## Public test boundaries

规格范围：D8–D9；D7 数据库中断时的连接区别；案例见[可追踪验收案例](../spec.md#可追踪验收案例)。

- 公开命令与可见结果配合真实隔离PostgreSQL的可复现I/O/提交故障；不能以mock COMMIT返回值代替真实事务结果证据。
- 包括开局、扣款、派奖、05补给和08自动事件；通过HTTP/WebSocket核对没有假成功与重复动作。
