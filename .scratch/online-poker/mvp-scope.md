# 明天最小可玩版本的范围

Status: scope-agreed
Target date: 2026-10-09 (Asia/Singapore)

用户要求全部使用免费方案，并要求区分首版必须具备的规则与可后续增加的功能。
用户在 Q13 回答“是”，确认首版范围和延期优先级。本文件不是完整规格或云平台选择，
具体行为中标记待确认的项目仍须逐项讨论。已确认规则以
[需求讨论记录](requirements-discussion.md) 为准，首版不能静默删改已确认要求。

## 首版必须具备

| 范围 | 必须具备的行为 | 决策状态 |
| --- | --- | --- |
| 房间与参与者 | 一个房间、最多两个真人、每局一个机器人；首位真人为房主，只有房主开局 | 用户明确要求；开局人数、换房主、中途加入待确认 |
| 发牌与比牌 | 52 张无大小王牌；两张手牌、最多五张公共牌；最佳五张；十类牌型、点数与自定义花色比较 | Q1–Q6、Q9 已确认；手牌可见性待确认 |
| 完整牌局 | 翻牌前、翻牌、转牌、河牌、摊牌；只剩一名未弃牌玩家时提前结束 | Q9 已确认；座位、盲注轮换、行动顺序和下注轮结束条件待确认 |
| 合法下注 | 无限注；弃牌、过牌、跟注、下注/加注、全押；小盲 1、大盲 2，无前注、不涨盲；普通最低下注与加注限制；筹码不足按剩余金额全押；短全押按完整加注门槛判断加注权 | Q10–Q12、Q14–Q15 已确认 |
| 正确筹码结算 | 整数 chips，平局赢家平分及零头分配，不透支、不重复扣款；全押时按各玩家投入划分可争夺底池 | Q7–Q8 已确认；边池、无人跟注的超额下注处理待确认，不能忽略三人无限注中会出现的边界 |
| 简单机器人 | 每局能按合法行动完成牌局，不接触真人隐藏手牌；机器人策略与流程的每行代码逻辑有中文注释 | 简单策略与注释为明确要求；打法、等待时间和余额生命周期待确认 |
| 身份与存档 | 首次每人 100 chips，余额累计；关闭再打开连贯；已保存 chips 跨服务重启保留 | 用户明确要求；身份方式、写入时点和数据模型待确认 |
| 退出与异常 | 中途退出已下注 chips 不退；断线、超时、刷新与重复请求不应卡局或重复记账 | 退出约束已明确；退出判定、全押后退出、重连和超时规则待确认 |
| 实时页面与上线 | Go + HTML/JS/CSS；可见房间、牌桌、筹码、当前行动与结果；支持 WebSocket 的免费部署与持久数据库 | 技术方向和上线约束已给出；部署、存档、交互及验收边界待确认 |

保存 chips 跨重启与恢复未完成牌局需分开确认：不能默认重启后重新发 100 chips，
也不能只在正常结算时保存而忽略已扣筹码、底池与未完成牌局的关系。
免费数据库休眠或临时不可用时的开局/行动策略仍待确认，不能默认先游戏后补存。

## 后续增强功能

- 更强的机器人：胜率估算、诈唬、多种风格和难度。
- 完整账号系统、跨设备登录、昵称资料和找回身份。
- 聊天、排行榜、详细战绩、牌局回放。
- 页面动画、音效和精细视觉设计。
- 多实例部署、自动扩容、高可用与无感故障切换。

Q13 已确认复杂机器人、完整账号与跨设备登录、聊天、排行榜、回放、动画和音效可以后加。
其他增强项不纳入首版；以上均不是已承诺实现的功能清单。
匿名身份是否足以满足首版仍需要用户确认。
持久筹码、正确结算、基本重连处理和服务重启后未完成牌局的明确处理策略，不能作为
视觉或工程增强项一起延期。完整继续原牌局并非已明确要求，但能否延期须在确认重启策略后判断。

## 当前明确排除

- 大厅与多房间。
- 自动涨盲、额外前注。

它们属于已明确排除的行为，不作为本次首版或已承诺的后续任务；未来改变需要重新确认。

## 上线前必须验证

- 真人与机器人能完成一局，并进入下一局；行为符合最终确认规格。
- 不同余额全押、平局零头、弃牌与退出的筹码结算可复现。
- 非本人回合、非法金额、重复行动与隐藏手牌权限有明确处理。
- 页面关闭/重开，以及已保存 chips 跨服务重启，按最终确认行为验证。
- 用实际选定免费平台验证 HTTPS/WSS、休眠后重连与存档读取。
- 记录官方免费额度、是否要求信用卡及休眠/清理限制，不把试用额度当成永久免费。

验收案例和公开测试边界将在需求确认后写入规格；这些条目暂不代表已有实现或测试通过。
