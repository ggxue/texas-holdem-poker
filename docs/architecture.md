# 当前实现结构

## 房间、存档与并发

`internal/poker` 提供一个 HTTP Handler，封装匿名凭证、房间命令、持久提交及按身份可见状态。
调用者提供 PostgreSQL 连接池并负责关闭池；应用关闭负责释放自己的 WebSocket。
网页和测试经过同一 HTTP/WebSocket 入口，不暴露线上改余额或改牌入口。

选择 PostgreSQL 单行 JSONB 房间快照，包含全部钱包与房间状态；另存匿名 Cookie 签名密钥
和按身份/请求标识唯一的命令结果。凭证本身不出现在公共房间视图。
这是一间小房间的实现选择，并非新增产品规则，也不声称数据库配额可以无限保存历史。

同一进程的命令和连接注册使用应用互斥锁。跨事务的权威顺序由 PostgreSQL 房间行锁决定，
所有命令先获得行锁，再核查持久请求结果和当前版本；新状态及命令结果同事务提交。
该顺序也让重试等待前次事务结束，不能凭一次无锁查询断言请求没执行。
提交成功后才更新页面；内存连接列表只是通知目标，不承担余额存档。

锁顺序固定为应用锁 → PostgreSQL 房间行锁。网络写入由每个连接自己的写循环负责，
不在房间锁下等待客户端读取；通知队列满则关闭该连接。
HTTP 请求和数据库操作都有取消/超时约束。

本票仅完成入房基础。完整页面接管、离房和超时、提交结果不明、牌局恢复、
新进程隔离旧进程分别属于票据 07–11，不能把基础行锁当作已通过那些验收。
