# 当前实现结构

本页描述升级后的当前实现：五真人容量、每局随机行动起点、机器人思考等待和六座位布局。
行为契约见[牌桌升级规格](../.scratch/poker-table-upgrade/spec.md)，
本地验收及外部环境限制见[升级证据](../.scratch/poker-table-upgrade/acceptance-evidence.md)。

当前规则见[规格](../.scratch/online-poker/spec.md)和[内存决定](../.scratch/online-poker/memory-reset-decision.md)。

internal/poker 的 App 提供 HTTP Handler，拥有身份、唯一房间、钱包、牌局、
控制页、期限和请求结果。全部只在进程内存中；New 使用真实洗牌与时钟，
NewWithOptions 允许公开测试 seam 控制牌序、时间、行动起点和机器人思考秒数，
不在线上暴露改牌、改筹码或控制随机输入的接口。
cards.go 比较最佳五张；game.go 负责底注、四动作、机器人、单池结算；
deadlines.go 处理真人行动期限、机器人思考期限、连接宽限和同刻离房优先。

房间有五个真人座位和一个固定机器人座位；房主移交按仍在房真人的入房先后。
每局从本局参赛者中等概率选择一次行动起点，各轮行动与平局零头沿同一座位循环。
机器人每次合法行动机会独立等概率抽取1–8整数秒，安排到期动作，等待期间释放锁。
实际思考期限与页面30秒倒计时依据分开保存；接管不重抽，下一真人获得完整30秒。
提前结算取消旧机会，迟到的旧回调不能操作下一局。

App.mu 串行保护变更及连接注册；视图在锁内按身份裁剪复制，响应在解锁后发送。
WebSocket 使用有界队列和独立写循环，队列满即关闭，网络写有期限。
服务器决定合法动作、扣款及结果，客户端只显示已确认版本。
前端按固定座位呈现桌面与手机布局，cards.js提供简洁牌面与十类牌型参考。
公共状态提供本局起点、思考标识及倒计时依据；结算结果在操作区下方展示，
使用按身份裁剪的服务器结果，并保留至下一局开始。
请求去重只在本进程有效，同标识换内容及过期控制页请求拒绝。
新页面接管旧控制页；旧连接关闭事件不能让新页离房。

每次成功的新入房请求将本人可用余额设为100，同一请求重试和GET不补给；
已经投入底池的筹码不退。本局参赛身份固定，中途占用同座位不能继承手牌。
普通断线保留30秒，行动期限独立且重连不延长。
入房后尚未建立WebSocket也有限期，反复请求不能无限保留座位。
牌局推进、机器人和期限的逻辑逐行以中文解释。

匿名Cookie使用本进程随机密钥签名；进程结束后密钥和状态全部丢失，
旧Cookie进入新进程时创建新身份。没有数据库、文件存档或跨进程共享。
/healthz 只检查服务状态，不创建身份。关闭应用取消期限与连接。
部署必须单实例；平台滚动替换仍可能短暂同时存在两个独立进程，
因此安排无进行中牌局的维护窗口，不承诺无缝迁移。
