# 当前实现结构

当前决定见[内存与重连规则](../.scratch/online-poker/memory-reset-decision.md)。

internal/poker提供HTTP Handler，封装身份、唯一房间、入房及按身份可见状态。
App拥有房间和请求结果，全部只在内存中；New不接收数据库或外部配置。
匿名Cookie由本进程生成的随机密钥签发；新进程不识别旧进程凭证，不恢复旧牌局。

App.mu串行保护房间变更、请求结果和连接注册。所有状态视图在锁内复制，
HTTP响应在解锁后发送，并设置写期限；WebSocket由独立写循环发送，有写期限。
锁内只向有界通知队列投递，不等待客户端读；队列满时关闭连接。
同一请求结果仅在进程存活期内保存，版本校验也只针对当前内存状态。

每次成功的新入房请求将本人余额设为100，包括重连；同一请求重试返回原结果。
不改变别人的余额，不退回已投入底池的筹码。GET不会补给。
完整页面接管、离房、期限和牌局仍由后续票据实现；没有数据库故障或重启恢复模块。
